=== CLAUDE-FORMAT PROMPT TEMPLATE ===

Output layout for any framework when the target model is Claude.
The framework decides WHAT goes in; this template decides HOW it is laid out.
Delete tags that carry nothing. Keep tag names identical across related prompts.

─────────────────────────────────────────────
FRAMEWORK COMPONENT → CLAUDE TAG
─────────────────────────────────────────────
Role / Capacity / Persona        → first sentence (or system prompt)
Context / Background / Insight   → <context>
Input / documents / data         → <input> or <documents>  (placed FIRST, above instructions)
Objective / Task / Action / Ask  → <instructions>  (or the closing query line)
Steps / Principles               → numbered list inside <instructions>
Rules / Do / Don't / Narrowing   → <rules> (state each as a positive action; add the reason)
Examples                         → <examples><example>..</example></examples>
Audience / Tone / Style          → <audience>, <tone>, <style>  (or one line in <context>)
Format / Expectation / End goal  → <output_format>
Key Results / success criteria   → <success_criteria>

─────────────────────────────────────────────
TEMPLATE
─────────────────────────────────────────────

[One-sentence role, e.g. "You are a senior data analyst reviewing quarterly reports."]

<documents>
  <document index="1">
    <source>[file name or origin]</source>
    <document_content>
    [long input pasted or {{VARIABLE}}]
    </document_content>
  </document>
</documents>

<context>
[Who this is for, why the task exists, and the reason behind any non-obvious rule.]
</context>

<instructions>
[Direct, specific, positive. Ask for the depth you want ("go beyond the basics").]
1. [step, only if order matters]
2. [step]
</instructions>

<rules>
- [Do X, because Y.]
- [Keep Z unchanged.]
</rules>

<examples>
  <example>
    <input>[sample input]</input>
    <output>[ideal output]</output>
  </example>
  [3-5 examples; vary them so no unintended pattern is learned]
</examples>

<output_format>
[Structure, length, tone. Optionally: "Put the final answer in <answer> tags."]
</output_format>

[Closing task line: the actual question or request, placed LAST after any long data.]

─────────────────────────────────────────────
OPTIONAL BEHAVIOR BLOCKS (system prompts, agents)
─────────────────────────────────────────────
<default_to_action>
By default, implement changes rather than only suggesting them. If intent is unclear, infer the most useful action and proceed, using tools to find missing details.
</default_to_action>

<investigate_before_answering>
Never make claims about code or files you have not opened. Read the relevant files before answering.
</investigate_before_answering>

<use_parallel_tool_calls>
Run independent tool calls in parallel; run dependent calls sequentially. Never guess missing parameters.
</use_parallel_tool_calls>

Confirm-before-risk (add for agents with write access):
Take local, reversible actions freely. Ask before destructive, hard-to-reverse, or outward-facing actions.

─────────────────────────────────────────────
CHECKLIST BEFORE DELIVERING
─────────────────────────────────────────────
[ ] Would a colleague with no context follow this without questions?
[ ] Long data above the instructions, task last?
[ ] Every prohibition rewritten as a positive instruction with a reason?
[ ] No ALL-CAPS "MUST/NEVER/CRITICAL" emphasis (soften to plain "Use X when Y")?
[ ] Examples inside <example> tags, 3-5, diverse?
[ ] No prefilled assistant turn, no "write your reasoning in <thinking> tags" for newest models?
[ ] Effort/thinking controlled by settings, not by wording?
