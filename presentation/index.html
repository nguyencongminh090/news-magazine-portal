Multi-Layered Security & Session Lifecycle (ADR-002)

Password Hardening & Session Lifecycles

  • Argon2id Password Hashing: Modern memory-hard hashing (memory cost 64MB, 3 iterations, 4 parallelism lanes). Passwords checked against a known weak-password blocklist with constant-time verification.
  • Ephemeral In-Memory Access Tokens (15 min): HS256 JWT stored strictly in JavaScript closure memory. Never written to localStorage or sessionStorage, rendering credentials immune to XSS exfiltration.
  • Refresh Token Rotation (14 days): Transmitted via HttpOnly; Secure; SameSite=Strict cookie, hashed with SHA-256 before DB insertion. Replay of an expired token revokes the entire family_id with a 30s grace window for multi-tab sync.
  • CSRF & Transport Guard: Enforces X-Requested-With: fetch header check and Origin allowlist validation.

Access Control & Abuse Prevention

  • Database-Backed Auth Middleware: Every authenticated request re-checks is_active, roles, and password_changed_at against PostgreSQL, enabling instant administrative revocation without waiting for token expiration.
  • Email Verification Gate: Single-use cryptographically random tokens. Unverified users are permitted to read articles but barred from posting comments, ratings, likes, or user tags.
  • Hierarchical Rate Limiting: Tiered limits per IP + email for auth endpoints (preventing brute-force and credential stuffing), and per user ID for comments and ratings (returning HTTP 429 + Retry-After).
  • Defensive Encoding: Parameterized SQL (100% SQLi immune), Zod .strict() blocking mass-assignment, Helmet CSP, and HTML entity sanitization.

Why SQL LIKE Fails: Relational DB vs IR Pipeline

Relational SQL Search: ILIKE '%term%'

  • Exhaustive Table Scans: $O(N)$ computational complexity requiring sequential scans across every row in the database, resulting in heavy disk I/O as corpus scales.
  • Binary Matching Only: An article either matches or does not match. Relational databases cannot determine whether a document is slightly relevant or critically relevant.
  • Lack of Term Saturation: A document mentioning a word 50 times is treated identically to one mentioning it once, or biased unfairly without diminishing returns.
  • Field Blindness: Relational queries treat a match in a footnote identically to a match in the article headline, lacking field weighting.
  • Linguistic Rigidity: Cannot handle morphological variants (voting vs vote), synonyms, or typos without computationally brutal regex operations.

Custom IR Search Engine (SEG301m)

  • Inverted Indexing in RAM: Inverts document mappings into a vocabulary dictionary; query execution only touches posting lists of active query terms, achieving 0.226 ms latency.
  • Graded Relevance Scoring: Evaluates document relevance using term frequency (TF), inverse document frequency (IDF), and document length normalization.
  • Fielded Saturation (BM25F): Distinct weights per field ($w_{\text{title}}=3.0, w_{\text{tags}}=2.2$) with non-linear saturation preventing keyword stuffing.
  • Morphological Normalization: Porter Stemmer conflates related grammatical forms; 3-shingle detects near-duplicates; noisy-channel corrects typos.
  • Postings Compression: V-Byte Delta compression reduces memory footprint by 75.0% with skip pointers accelerating conjunctive evaluation.

Text Processing: Tokenization, Stemming & Shingling (Ch. 4)

Step 1

Lexical Tokenizer

Strips HTML tags & entities; splits text via [a-z0-9]+ regex into normalized lowercase tokens; records character start/end offsets for safe snippet highlighting.

Step 2

Stopword Filter

Filters 128 high-frequency grammatical words (the, is, which, at, on) that consume posting space while contributing negligible topical discrimination.

Step 3

Porter Stemmer

Executes classical 5-phase suffix-stripping rules (e.g. caresses → caress, ponies → poni, elections → elect, voting → vote) with measure $m$ consonant checks.

Step 4

3-Shingle Dedup

Constructs sliding 3-token shingles; computes pairwise Jaccard similarity $J(S_1, S_2) = \frac{|S_1 \cap S_2|}{|S_1 \cup S_2|}$ to flag syndicated wire duplicates ($J > 0.50$).

Porter Stemmer Phase Invariants (Chapter 4.3)

  • Step 1a & 1b: Plurals and verb inflections (SSES → SS, IED → I, (*v*)ING → ε).
  • Step 2 & 3: Derivational suffix stripping (ATIONAL → ATE, FULNESS → FUL).
  • Step 4 & 5: Residual endings and trailing -e reduction governed by syllable measure $m > 1$.

Storage Compression: Delta (d-gap) + Variable-Byte (Ch. 5)

Delta (d-gap) Encoding

D-Gap Transformation

Replaces monotonically increasing doc IDs with gaps between consecutive entries: $\Delta_i = \text{docId}_i - \text{docId}_{i-1}$.

Raw IDs: [1, 5, 9, 18, 128, 300]
→ Gaps: [1, 4, 4, 9, 110, 172]

Gaps for common terms remain small, allowing most values to pack into a single 8-bit byte.

Variable-Byte (V-Byte)

7-Bit Continuation Format

Each byte carries 7 bits of payload. The most significant bit (MSB, bit 7) acts as the continuation flag:

  • MSB = 0: Non-terminal byte; more bytes follow.
  • MSB = 1: Terminal byte of current integer.
  • Values < 128 require exactly 1 byte; values up to 16,384 take 2 bytes.

Conjunctive Query Acceleration: Skip Pointers (Ch. 5)

Skip Pointers Formulation (Chapter 5.3 & 5.7)

For a posting list of length $P$, skip links are placed at optimal fixed intervals of length:

Stride Step: $L = \lfloor\sqrt{P}\rfloor$

Skip-Assisted Merge Algorithm: When intersecting posting list $A$ with list $B$:

  • If $B[j] > A[i]$, check if index $i$ has a skip pointer to $i + L$.
  • If $B[j] \ge A[i + L]$, advance pointer $i$ directly to $i + L$, skipping $L - 1$ postings in a single jump!
  • Reduces worst-case merge comparisons from $O(P_1 + P_2)$ to $O(\sqrt{P_1} + \sqrt{P_2})$.

Spelling Correction: Damerau-Levenshtein & Noisy Channel (Ch. 6)

Optimal String Alignment

Damerau-Levenshtein Edit Distance

Classical Levenshtein penalizes adjacent character swaps twice (one deletion + one insertion). Damerau-Levenshtein adds adjacent transposition as an atomic cost of 1:

Cost = min(Insert, Delete, Substitute, Transpose)
  • damerauLevenshtein("brimingham", "birmingham") = 1
  • damerauLevenshtein("extenssions", "extensions") = 1
  • Limits search to candidates within max edit distance $\le 2$.
Bayesian Noisy Channel

Noisy Channel Scoring Formulation

Finds candidate word $\hat{w} \in V$ that maximizes the posterior probability given observed error string $e$:

$\hat{w} = \arg\max_{w \in V} P(e|w) \cdot P(w)$
  • Error Model $P(e|w)$: $\exp(-3.0 \cdot \text{dist}(e, w))$, decaying exponentially as edit distance increases.
  • Language Model Prior $P(w)$: $\frac{\text{freq}(w) + 0.5}{N + |V|}$, favoring common corpus words via Laplace smoothing.
  • Verified: manchesterr electon → manchester election.

Retrieval Models I: Fielded Okapi BM25F vs TF-IDF (Ch. 7)

Production Model

Fielded Okapi BM25F Formulation

$\text{Score}(D, Q) = \sum_{t \in Q} \text{IDF}(t) \cdot \frac{\tilde{\text{tf}}(t, D) (k_1 + 1)}{\tilde{\text{tf}}(t, D) + k_1 (1 - b + b \frac{|D|}{\text{avgdl}})} \cdot \frac{(k_2 + 1) qf}{k_2 + qf}$

  • $k_1 = 1.2$: Calibrates term frequency saturation curve.
  • $b = 0.75$: Controls document length penalty.
  • $k_2 = 100$: Controls query term frequency saturation.
  • Field-Weighted TF: $\tilde{\text{tf}} = 3.0 \cdot \text{tf}_{\text{title}} + 2.2 \cdot \text{tf}_{\text{tags}} + 2.0 \cdot \text{tf}_{\text{seo}} + 1.5 \cdot \text{tf}_{\text{summary}} + 1.0 \cdot \text{tf}_{\text{content}}$.
  • Robertson-Spärck Jones IDF: $\ln(\frac{N - df + 0.5}{df + 0.5} + 1)$.
Vector Space Baseline

TF-IDF Cosine Similarity Formulation

$\text{Sim}(D, Q) = \frac{\vec{V}_D \cdot \vec{V}_Q}{||\vec{V}_D||_2 \cdot ||\vec{V}_Q||_2} = \frac{\sum_{t} w_{t, D} \cdot w_{t, Q}}{\sqrt{\sum w_{t, D}^2} \cdot \sqrt{\sum w_{t, Q}^2}}$

  • Sublinear TF Weighting: $w_{t, D} = (1 + \ln \text{tf}(t, D)) \cdot \text{IDF}(t)$.
  • Bounded Range: Score is strictly bounded in $[0, 1]$ via Euclidean vector normalization.
  • Structural Limitation: Lacks field distinction and non-linear saturation, causing long documents with repetitive terms to unfairly dominate.

Retrieval Models II: Query Likelihood Dirichlet LM (Ch. 7)

Generative Principle

Statistical Language Modeling

Treats search as generative probability: Documents are modeled as statistical unigram language generators $\theta_D$. Documents are ranked by the probability of generating query $Q$:

$P(Q|\theta_D) = \prod_{t \in Q} P(t|\theta_D)$

Zero-Frequency Catastrophe: If document $D$ is missing even one query term, Maximum Likelihood Estimation sets $P(t|D) = 0$, causing the entire product to collapse to zero.

Dirichlet Smoothing

Bayesian Dirichlet Prior Smoothing

Smooths document language model using background collection model $P(t|C) = \frac{\text{cf}(t)}{|C|}$ and Dirichlet prior $\mu \approx \text{avgdl} = 1500$:

$P(t|D) = \frac{\text{tf}(t, D) + \mu \cdot P(t|C)}{|D| + \mu}$

Log-Likelihood Ratio Scoring: Computed in log space against collection background: $\sum_{t \in Q} qf(t) \cdot \ln\left(\frac{P(t|D)}{P(t|C)}\right)$, penalizing ubiquitous words while avoiding floating-point underflow.

Combines Sequential Dependence bigram match ($0.6$) and Minimal Span Window covering all query terms ($0.4$): $\frac{|Q|}{\max(|Q|, \text{span}_{\min})}$.

Reader Engagement

Composite factor combining log view velocity ($0.7$) and Bayesian community rating ($0.3$), factoring crowd consensus into ranking.

Query Expansion: Dice Co-occurrence & RM3 PRF (Ch. 8)

Global Co-occurrence

Dice's Coefficient Matrix (Ch. 6 & 8)

Computes pairwise statistical term association based on co-occurrence across documents:

$D(w_i, w_j) = \frac{2 \cdot n_{ij}}{n_i + n_j}$
  • $n_{ij}$: Number of documents containing both terms.
  • $n_i, n_j$: Document frequencies of individual terms.
  • Evaluates top correlated terms across postings to suggest expansions (e.g., solar → photovoltaic, clean, grid).
Relevance Model 3

RM3 Pseudo-Relevance Feedback (Ch. 7)

Assumes the top $K=5$ retrieved documents in the initial ranking are relevant:

$P(w|R) = \sum_{D \in \text{TopK}} P(D|Q) \cdot \frac{\text{tf}(w, D)}{|D|} \cdot \text{IDF}(w)$
  • Extracts the top 5 most informative feedback terms.
  • Interpolates with query using feedback mixture $\alpha = 0.4$.
  • Re-executes search: Achieves perfect MRR = 1.000 in offline benchmark evaluation.

Error Taxonomy & Qualitative Failure Analysis (Ch. 9)

Type I · Lexical Gap

Vocabulary Mismatch

Failure: Query uses terms absent from corpus (e.g. "papacy tour" vs article "pope travelled to Africa").

Mitigation: RM3 PRF injects co-occurring feedback stems; Dice co-occurrence matrix ($D=\frac{2n_{ij}}{n_i+n_j}$) expands related terms.

Type II · Polysemy

Polysemous Query Ambiguity

Failure: Broad queries return discordant topics (e.g. "Green Party" political campaign vs renewable energy technology).

Mitigation: Post-retrieval K-Means clustering partitions results into distinct thematic centroids (election · parliament vs solar · energy).

Type III · Redundancy

Syndicated Wire Clones

Failure: Syndicated news wire stories (AP/Reuters) with minor timestamp edits crowd top-10 slots with identical facts.

Mitigation: 3-shingle Jaccard fingerprinting ($J > 0.50$) identifies near-duplicates at ingestion, suppressing clones from ranking.

Type IV: Zero-Frequency Collapse in Generative LM

Failure Mode: In un-smoothed Query Likelihood, if an article is missing even 1 of 4 query terms, $\prod P(t|D)$ collapses to 0, completely discarding an otherwise highly relevant story.

Architectural Fix: Bayesian Dirichlet prior smoothing ($\mu=1500$) incorporates background collection frequency $P(t|C)$, evaluating in log-likelihood ratio space: $\sum qf \cdot \ln(P(t|D)/P(t|C))$.

Type V: Negation Leakage in Unconstrained Vector Space

Failure Mode: Naive TF-IDF cosine accumulation on queries like "Obama NOT Biden" computes positive dot product for Obama, failing to eliminate articles mentioning Biden.

Architectural Fix: Query parser AST builds strict exclusion set $C_{\text{neg}}$, performing set subtraction $C_{\text{pos}} \setminus C_{\text{neg}}$ before rank scoring, ensuring 0% false positives.
